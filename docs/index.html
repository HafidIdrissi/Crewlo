YOUR WORKSPACE. CLEAR BOUNDARIES.

Local doesn’t mean
disconnected.

Crewlo runs on your computer. Your connected tools still have their own network, cost and permission boundaries.

01

Credentials stay out of the conversation.

Telegram and WhatsApp secrets use the operating system’s encrypted storage. Conversation history is stored locally, but is not encrypted by these integrations.

02

Your providers are still your providers.

Agent CLIs can send prompts and code to their providers. Telegram and Meta process messages on their platforms. Review those services before sharing sensitive work.

03

A phone message isn’t a permission override.

Messaging reuses agent sessions and delivery gates. Review the CLI’s approval settings; the transport does not make unsafe permission modes safe.

BEFORE YOU CLOCK IN

Good questions.
Straight answers.

Ask something else ↗
Is Crewlo an AI model?

No. It is a desktop workspace around agent CLIs you install and authenticate separately. Provider subscriptions, API usage and limits still apply. Coordination support varies by provider.

Is the demo running real agents?

The footage is recorded in Crewlo’s real interface, using scripted activity events and a simulated Telegram setup. It is not a live model run or proof of phone delivery. Read the capture notes.

Can I message it from my phone?

Telegram Bot API and WhatsApp Cloud API integrations are implemented in this branch. Both require setup, desktop confirmation and an available agent session. Local mocked integration tests pass; your real credentials and model still need a live test.

Does my computer need to stay on?

Yes. Keep Crewlo, the agent session and your network connection running. WhatsApp also needs your HTTPS webhook relay. Crewlo does not move your agents into a hosted background service.

Is it free? What about privacy?

Crewlo’s source is MIT-licensed. Your AI provider and messaging services may have their own costs. Local storage does not make external agent or messaging services offline; review their data policies and your permission settings.

Where can I make my first contribution?

Start with a reproducible bug, an accessibility improvement or a platform test. Read the contributor guide and describe a small change before opening a pull request.
